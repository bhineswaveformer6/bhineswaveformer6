# Brandon Hines

Founder, Waveform Tech · Full-stack AI and Web3 engineer

I build software that makes AI-assisted workflows easier to evaluate, govern, and inspect.

My current work focuses on three connected problems:

- Scoring: applying explicit, versioned evaluation rules.
- Workflow controls: allowing or blocking actions using recorded criteria.
- Traceability: preserving the evidence behind a decision.

## Current focus: CortexChain

CortexChain is the umbrella for my work on scoring tools, workflow gates, and traceable decision records.

I use “cognitive capital” as an organizing concept for this work. Proprietary scores such as QTAC₇ and Stone Score are experimental evaluation frameworks—not established scientific measures of intelligence, human value, or investment performance.

## Intended workflow

Submit a sample work record → evaluate it against a versioned rubric → apply a configured gate → inspect the resulting decision record.

This describes the intended system flow, not a verified end-to-end demonstration. Implementation status, access requirements, and limitations should be evaluated for each project separately. Scoring thresholds are framework policy choices, not validated measures of human capability or investment quality.

## How to evaluate the work

The useful questions are concrete:

- What input is being evaluated, and which rules and versions apply?
- Can the result be reproduced from the same inputs?
- What action does a gate permit or block, and where is that control enforced?
- What evidence is retained, and what integrity guarantees are actually implemented?
- Which features are implemented, experimental, or planned?

Specifications describe intended behavior; source code, reproducible examples, and tests are needed to establish implementation. A linked interface alone does not establish validation, security, or production readiness.
